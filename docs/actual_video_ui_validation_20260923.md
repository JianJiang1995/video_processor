## 已修正的问题

### 模拟源会话没有固定原视频

此前 `simulator://capture-card/0` 会解析当前全局默认文件。切换输入后，旧会话可能误读新文件。
现在模拟源支持在 UI 输入本地路径，新会话保存 `simulator://file/<转义后的绝对路径>`，同时保留布局信息。
内存与 MySQL 保存相同 URI；绑定文件缺失时明确报错，不回退到其他视频。
历史重新分析也允许从绑定原文件补取帧，不访问当前采集设备。

涉及 `local_video_source.py`、`routers/video.py`、`StreamInput.vue`、`window_reanalysis.py`。
测试覆盖文件路径转义、裁剪尺寸、双存储一致、缺失文件不得悄悄换源。

### 抓钳被单次复核升级为正在施夹

首轮会话 `967ca549` 中，约 70–75 秒和 435–450 秒可见带开孔的抓钳。
原始主 VLM 均没有判断正在施夹，YOLO 主要判抓钳，但形态复核却返回施夹器，覆盖了前面的结果。
这还会推进不可回退的阶段状态，让后续阶段一起出错。

现在单次形态复核不能在缺乏主视觉、跨帧器械检测或明确载夹证据时独自升级施夹结论。
被拒绝的候选和理由保留在结构化记录，原始模型响应不删除。
不使用文件名、窗口号、时间点判断器械类别。文中的时间仅用于测试定位。

### 删除器械描述后遗留无主语动作

全图复核明确无器械且 YOLO 同样无器械时，清理规则现在同时清除依赖该主语的“仅见其在移动”等句子。
没有器械清单或检测器实际支持器械时，不套用这个否定规则。

### 场景证据未进入复核

原主 VLM 的 observations 会被规范化函数丢弃。例如模型已描述皮肤切口，却在 visibility 中仍填 clear，结果没有触发体外复核。
现在保存观察列表，皮肤、手术巾、设备、袋膜/袋口等肯定线索会触发图像复核，不直接决定分类。
历史窗口重新分析也复用该机制。体外仍需明确证据类型和不同帧的支持。
第一段 400–415 秒的三个漏检候选来自对全部原始 observations 的扫描，不是运行时按时间写答案。

### 录像缺失前半程不等于后续动作不可能

经过主视觉与场景复核确认的标本袋，可以保留为当前阶段，即使本文件里没有前面的夹闭步骤。
这不会补写 CVS 达成、夹闭过哪条结构、或已经剪断。
第二段首轮复核把网状纱布误当标本袋，曾让这个放行条件错误推进阶段，已中止该轮。
现要求主视觉对袋膜/袋口的跨帧观察与场景复核相互支持；单次复核不能覆盖主模型的纱布观察。
提示词也区分编织网格/显影线与塑料袋膜，区分纱布遮挡、运动失焦与真正雾气。
负例约 150 秒与真实标本袋正例约 300 秒均保留原图、提示词和模型响应，规则不读取这些时间。

### 回放入口

连接页和模式选择页新增“导入分析回放”。选择每段目录里的 `analysis.replay.json`，可加载该段视频、窗口结果、事件与 Markdown 报告。
回放媒体是原片的右侧主视图派生文件；不是重新采集，也不会修改原视频。

导入后停在结尾，全部窗口和“视频总结”立即可用，可点击时间轴回到任意位置播放。
网格内的片段播放器独立于主播放器，退出后不会改变主播放器进度。

复测发现原 `file://` 转发没有返回 Content-Length / Accept-Ranges，浏览器认为只可定位到 0 秒。
新增 `frontend/electron/replayMedia.cjs` 流式分段读取，支持 GET、HEAD、206、416，内存不装载整段录像。
Electron 已重启加载修复；通过真实系统文件选择对话框导入成功。
事件缩略图改为优先加载可见事件，离线回放不再在入口预先排队生成全部 218 个窗口封面。

### 阶段模板不能盖掉实际画面

已有逐帧观察时，阶段状态不能再把实际摘要替换成“将胆囊装入标本袋”等模板动作。
录像从中途开始可以标记 `history_prefix_unknown`，允许以观察到的阶段进入，但不补造之前的步骤。
仅有体外画面的短片阶段为 Unknown，不推断肝胆三角操作或 CVS 未达成。
对已存原始 VLM 响应重新应用同一套通用规则，保留之前的摘要和 phase。
这一步不等于重新做了一次模型推理，记录标记为 `offline_narrative_reconciliation`。

### 先区分体内/体外，再判断成像质量

第二段 385 秒和 430 秒附近的设备画面被当成腹腔内起雾。
场景提示词增加通用区别：主体画面的真实设备、线缆、支架、墙面具有空间透视，不等于角落设备 UI；
体外场景也可以模糊或有雾，不能因为模糊就改判为腹腔内起雾。
原图重新送入本地 VLM 后，两处均自行返回 external_body 和多个支持帧。
对照测试：纱布仍为腹腔内，透明标本袋仍为 specimen_bag_inside，普通腹腔画面仍为 intra_abdominal。
这些测试时间只用于复现和比较，不出现在运行时判断代码中。
展示文本仅整合已接受的场景类型；模型原始回答中的图片序号、设备品牌猜测保留在审计数据，不直接展示。

另修正起雾状态的持续红色：有起雾记录后，连续两个相邻窗口明确为腹腔内清晰视野且置信度至少 0.75，
才转为“雾已去除”。未知、缺失窗口、单个清晰帧或体外画面不能解除起雾状态。
普通 blurred/blocked 不再直接等同于 foggy；新的雾气证据仍可重新开启该节点。
这个 UI 状态修正的三段回归录屏在 `ui_checks_visibility_final`，不改写模型原始记录。

## 明确未解决的准确性问题

- 第一段窗口 15 的“器械夹持肠管”仍可能把脂肪/邻近组织过度具体化。移除了错误施夹升级，不代表解剖对象已经确认。
- 第二段窗口 60 将袋内标本称为“肿物”，不能把这个视觉模型用词当作病理诊断；标本袋操作可见，但标本性质需要医生确认。
- 第一段 410 秒、第二段 440 秒的场景切换只有一个采样帧支持体外，未达到跨帧门槛，仍有漏标短事件的风险。
- 模型对雾气、失焦、运动模糊仍不能始终可靠区分；阶段预测可能提前进入后续阶段，部分器械仍只描述为“器械”。
- 阶段汇总沿用模型阶段判断，报告的阶段标题也需复核。CVS 未形成达成结论不等于患者实际未达成 CVS。
- 最终窗口仍落后约 18–19 秒，未达到 5 秒目标。离线回放加载速度不能冒充实时分析延迟。

这些是后续应优先核查的模型问题，不以时间规则或逐片段写答案掩盖。

## 验收边界

这属于软件与模型行为测试，不是医生标注的临床准确率验证。
仍需核对器械名称、具体组织、阶段、静态夹体与实时施夹、起雾与失焦、体外场景、装袋和活动出血。
模型置信度并非经过校准的准确率。未见某步骤不等于该步骤没有在录像开始前完成。
首轮曾插入独立本地模型探测，共用 VLM 显卡，因此不作为纯实时负载的延迟基准。

## 复现

启动完整服务与软件：项目根目录执行 `./start_surgical_app.sh --keep-services`。
在连接页面选择“手术室采集卡模拟源”，填写本地视频绝对路径，选择“是，左三右一”，连接后自动分析。
不要选择真实 DeckLink 设备来处理这些本地文件。

测试录屏脚本（需打开本地 Electron CDP 9222，DevTools 不必显示）：

```bash
../.venv/bin/python scripts/record_live_retest.py \
  --video /绝对路径/video.mp4 --layout quad_right \
  --output recordings/新的测试目录 --tail 30
```

完成后导出：

```bash
../.venv/bin/python scripts/export_ui_session.py \
  --session 会话编号 --output recordings/对应测试目录
```

脚本会检查后台已结束、视频窗口覆盖数，并保留未通过的实际状态；不会把尚未完成的后台复核当作完成。
