# 初稿延迟与组织识别回归记录（2026-09-23）

## 目的与边界

检查 SurgR1 是否阻塞初稿，修复组织名称被规则错误补全、竞争候选被并列成事实的问题，并用原始长视频在 Electron 中按真实速度重新分析、录屏。

不按视频名、窗口号或时间段指定识别答案。所有模型调用留在本机。本文是工程验证记录，不是经医生标注确认的临床准确率报告。

上一版回滚点：`7d41963`；更早的工作流检查点：`b042bbb`。

## 初稿与后更新

实际执行顺序：

1. 采集线程按源时间保存帧，划分半开区间 `[start, end)` 的 5 秒窗口。
2. Phase、Triplet、器械 YOLO、夹子检测器及图像特征生成初稿。
3. 初稿提交数据库后，立即唤醒该会话的 SSE 连接。
4. 初稿已保存后才创建异步后更新任务。SurgR1 使用同窗已有的两张图，不开第二个解码器、不推动播放游标。
5. 本地 Qwen3-VL 结合三张全视图与专家候选复核，必要时做器械/场景专项复核，更新同一个窗口。

R1 不在初稿的等待链上，但 GPU 0 同时承载 R1 和小型专家，不能宣称绝对没有资源竞争。GPU 1 运行 Qwen3-VL。这里实际检测到的是两张 RTX 4090。

### 延迟的测量口径

- `source_window_end_wall`：无暂停、按真实速度输入时，首帧墙钟锚点加窗口结束时间。
- `window_ready_wall`：调度器发现可处理窗口的时间。
- `expert_ms`：专家预处理、推理及初稿构建耗时，另记录各组件耗时。
- `stage1_ready_to_save_wall`：开始保存初稿前的时间，不冒称数据库提交时间。
- `emitted_at_wall`：服务端发出 SSE 的时间。
- `received_wall`：真实 Electron 页面现有 EventSource 收到消息的时间。

初稿延迟 = `received_wall - source_window_end_wall`。它不包含“凑齐一个 5 秒窗口”之前的等待。不能再用测试脚本的启动时间或每秒轮询的观测时间代替模型延迟。

这套墙钟测量适用于本次不暂停的实时节奏测试。暂停、跳转、时间校准后的会话不能直接沿用这个公式；生产窗口归属仍依赖源时间戳，而非该诊断墙钟。

## 4K 输入与启动开销

原始输入为 3840×2160、50fps；四分图配置裁剪最右侧后为 2880×2160。早期长跑发现专家预处理仍重复处理大尺寸 RGB/BGR，稳定段初稿约 4 秒。

修改：

- 专家输入长边限制为 1280，不裁掉该视图内容，不改变源文件、播放视频及时间戳。
- 对文件 JPEG 使用独立解码器的缩小解码，不修改共享 PIL 图像；R1/VLM 仍从原同窗图像选择输入。
- Phase 真正按批推理，最多 16 张一批，不再把 `classify_batch` 实现成单帧循环。
- 后端启动阶段完成 4:3、16:9 画幅及实际批次的预热后再提供服务，最后重置器械追踪状态。
- SurgR1 的转换、缩放和 JPEG 编码整体在线程中执行，不占用接收和推送初稿的事件循环。
- 连通区域的颜色统计只遍历该区域的包围框，不再对每个候选重复扫描全图；回归测试确认与原全图统计结果相同，没有改变判断阈值或指定识别答案。

保留了中断的诊断录屏 `pilot_4k_before_resize`、`pilot_cold_start`、`pilot_tissue_competition`、`pilot_before_r1_threading`，它们不是最终成片。启动尖峰与稳定段必须分开报告，不能只选较快窗口。

## 组织混淆的修复

### 初稿

删除“仅凭阶段与器械存在”补出牵拉胆囊颈、分离肝床粘连、装袋、取出等操作的逻辑。

Triplet 的多标签候选不等于同一抓钳同时操作多个器官。对相同器械、相同动作的目标候选分组，只保留领先候选；与第二个不同目标的置信度差小于 0.15 时，不把竞争组织名全部写成事实。该阈值是保守展示门槛，不是经过临床校准的概率阈值。原始候选不删除，继续交给图像复核。

### 本地视觉后更新

- 明确区分背景器官、器械实际接触组织、胆囊本体与胆囊管。
- `observations` 同时保留器械、动作、接触组织、`target_evidence` 和有效帧编号。
- 本地视觉输入使用顺序帧编号，不再将绝对秒数放入同一识别提示，避免模型把 700 秒写成“第 700 帧”。原始时间仍在窗口和 R1 审计数据中保存。
- 英文规范器械/组织词做确定性中文术语映射，不根据颜色猜器官。
- 胆囊管/胆囊动脉摘要必须与观察记录及帧证据一致；无证据的关键结构标签不因默认值或 Triplet 弱候选被强行补齐。
- 本地路径不再把“牵拉组织”改写成“牵拉胆囊颈”，也不根据阶段把“分离胆囊”改成另一组织。外部 GPT 的原有提示和默认后处理路径不在本次改动中替换。
- 场景专项复核保留。R1 在体外也可能产生手术动作候选，不能把其回答直接视为真值。

## 最终长跑

### 历史接口与事件循环修正后的复测

继续定位发现，完整历史接口在异步路由中返回包含所有专家输出的嵌套结构，由 FastAPI 在主事件循环执行递归 JSON 转换；随窗口数增多，这会抢占初稿调度和 GPU 推理线程的 Python 执行时间。

修正为同步工作线程执行查询及一次 JSONResponse 序列化，保持响应字段和数据完全一致；SSE 的数据库读取也移入线程。没有删除原始模型审计信息，也没有降低检测采样。

对同一已完成的 218 窗数据，约 5.7 MB HTTP 响应，修正前单次约 0.955 秒，修正后三次约 0.387、0.602、0.335 秒。这不是严格受控性能基准，真正是否改善后段初稿仍由下一轮实时长跑检验。测试脚本每 3 秒获取全量审计结果，本身的负载也包含在延迟实测中。
