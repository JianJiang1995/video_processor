# 回看时间轴与返回分析进度

更新日期：2026-09-23。

## 操作约定

| 场景 | 拖动后 | 返回按钮 |
| --- | --- | --- |
| 本地视频正在分析 | 自由回看，后台继续分析 | 返回分析进度：暂停自由播放，定位最新已有分析的位置，并随新结果更新画面 |
| 已完成的离线结果 | 自由播放或暂停，保留全部窗口、事件和 Markdown 总结 | 定位最新分析：定位最后一个已有分析窗口 |
| 模拟实时源 | 用第二个播放器回看已播过的部分，原播放器继续推进 | 返回实时直播：关闭回看播放器，显示仍在运行的原直播 |
| 采集卡、网络实时源 | 在实际保留的帧缓存范围内回看，暂停仅影响回看 | 返回实时直播：恢复显示原实时画面 |

再次拖动或主动播放会退出离线的“跟随分析中”。普通进度条不会自动启用窗口循环；网格和片段回看弹窗仍有各自的独立循环播放功能。

分析进度表示最新**已产生结果**的源视频时间，不虚构尚在推理中的精确帧。帧级结果用 `timestamp`；只有窗口结果时用最新窗口的 `window_start`。状态每 3 秒查询一次，因此不是逐帧同步推理。

## 实现

- `App.vue` 分开维护主源时钟、回看时钟和分析进度。回看和离线拖动不再向后端发送 `seek`，离线播放、暂停也不控制分析任务。
- `ControlBar.vue` 使用原生 range 输入处理鼠标、触摸和键盘，去掉会与拖动争抢事件的旧播放头、窗口点击循环及全局拖动监听。
- `CachedHistoryPlayer.vue` 按 5 秒分块读取既有缓存，仅保留最多 4 个分块，请求可取消。缺失画面会明确显示缓存不可用，不用旧画面假装对应新时间。
- `/api/analysis/history-range/{session_id}` 只返回保存帧的实际边界，不把输入总时长当作可回看范围。缓存中间的缺口由播放器另行检测。
- `/api/analysis/surgr1-continuous-status/{session_id}` 用数据库聚合获取完整分析进度，避免原 `get_analyses` 默认上限 100 条和窗口 `timestamp=NULL` 导致定位失准。
- 导入结果在当前页面装载；入口自动跳转、自动接采集卡的定时器在导入或离开页面时取消。带 `replaySpec` 的启动不会先进入采集卡连接页。后端配置读取不阻塞本地回放。
- 完成的回放保留所有已存结果和报告，不因播放时间倒退删去“未来”窗口。右侧若正在显示旧窗口，明确标为当前播放窗口，不称为最新窗口。

## 限制

采集卡历史画面来自当前系统保留的预览/分析帧，并不是新增的全帧率录像系统。帧率、保留时长和画质受缓存策略限制；删除后的画面和未采集的未来画面不可回看。回看不会暂停采集或分析，也不会延长缓存保留期。
