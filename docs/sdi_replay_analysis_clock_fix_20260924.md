# SDI 实时分析被回放位置阻塞：修复与实测

## 原因

- 采集卡会话 `0ebb1112` 的 SDI 画面仍持续到达，帧保存线程也正常运行。
- 09:40:42 暂停预览写入 `current_position=256.5239`；09:41:16 恢复播放仍保留这个位置。
- `glm_summarization_task` 原来对所有 `is_live` 会话使用
  `min(last_capture_time, current_position + 1)` 作为分析就绪时间。
- DeckLink 预览通过采集状态推进，不持续发送文件播放器的 position 更新。因此一次暂停或回放退出留下的旧位置，会使后台永远停在旧窗口。这不是采集卡掉线，也不是模型退出。

## 改动

`backend/routers/analysis.py` 增加 `_analysis_source_elapsed`，用于窗口就绪判断：

- DeckLink、普通采集设备、RTSP、RTMP 只使用实际采集时间，不读取回放位置作为分析限制。
- 无固定片长的网络直播也不依赖浏览器位置。
- 有限文件模拟源仍受播放位置限制，且不能越过实际片尾。
- 离线分析不等待预览播放器，但仍不能越过片尾。
- 无信号时没有新采集时间，就不会凭墙钟生成新分析窗口。

本次没有修改模型、提示词、历史结果或手术识别规则，没有视频文件名/窗口编号特例。
