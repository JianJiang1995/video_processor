# 穿刺/点触识别功能落实总结

更新时间：2026-06-16

## 当前状态

穿刺/点触识别已经接入实时分析链路。现有流程不是单独硬编码，而是由专家模型初稿与额外 OpenVision/GPT 视觉模块共同补充：

- YOLO/Phase/Triplet 先给出实时专家快照，快速识别阶段、器械和基础动作。
- OpenVision/GPT 额外模块抽取窗口内压缩帧，专门补充专家模型未覆盖的短时动作、器械尖端接触、疑似穿刺/点触等事件。
- Gemini/LLM 汇总阶段会把 OpenVision 的关键证据合并进窗口摘要，后续精修覆盖时会保留这类高价值证据。

## 已观察到的效果

在当前测试流中，窗口 22/23 已经输出类似结果：

> 亮白细长器械尖端短时进入并接触组织，疑似穿孔/点触动作。

这说明额外 GPT/OpenVision 模块已经参与最终窗口分析，并且能够补充 YOLO/Triplet 原本没有稳定覆盖的短时穿刺/点触动作。

## 设计原则

- 不把“穿孔/穿刺”硬写死到结果里。
- 当视觉证据不充分时，使用“疑似穿孔/点触动作”这类保守描述。
- 最终摘要只显示综合判断，不暴露“YOLO 暂定”“后续精修覆盖”等内部过程文案。
- 英文 UI 下会通过轻量文本翻译接口把已有中文分析翻成英文，不重新做医学判断。

## 后续建议

- 若现场需要把“穿刺器从腹壁进入”作为强事件，可以继续增加独立候选字段，例如 `puncture_candidate`、`tip_contact_candidate`，用于 UI 高亮和后续人工复核。
- 如果要评估准确率，需要抽取含穿刺/非穿刺的标注片段，单独统计召回和误报。
- 目前窗口级摘要已经能显示该事件，但更严格的实时预警仍建议单独做事件检测阈值和时序平滑。
