## 当前配置

```json
"analysis_input_crop_right": {
    "quad_right": 0.11
}
```

- 先执行已有的四分图取右侧视图，随后仅在模型输入副本中裁掉最右边 11%。比例相对于取出的右侧视图，不是整个四分图。
- 保留左侧 89%、完整高度。当前两个图标都落在被移除区域。
- 原始文件、存储帧、界面播放、缩略图和历史回放画面不作这次裁剪。界面中仍看到图标是正常的，不表示模型收到图标。
- 窗口起止时间、图片采样时间、实时流时钟不变。
- 配置按输入布局生效，不依赖视频名、时间点或模型预期答案。当前只启用 `quad_right`，普通 `full` 输入不自动裁剪；采集卡、模拟源、本地文件选中相同布局时使用同一规则。
- 这是设备叠加层配置，不是通用于所有设备的解剖区域规则。更换设备或输出布局时必须复核图标位置。右侧 11% 内的真实器械、组织也不会参与识别，这是固定整条裁剪的代价。

## 输入链路

`backend/services/analysis_image_regions.py` 是统一处理入口：读取布局配置，在模型私有副本上处理，记录裁剪比例，消费待应用的裁剪元数据。

| 路径 | 接入点 | 本次实际输入尺寸示例 |
| --- | --- | --- |
| YOLO、Phase、Triplet、夹子检测 | `prepare_expert_frame` 后进入共同 `frames_bgr` | 1139 x 960 |
| 本地 VLM、独立器械和场景复核 | `_fit_image_for_vlm` | 569 x 480（640边长配置） |
| SurgR1 异步窗口复核 | `_write_review_image` 保存私有 JPEG | 747 x 630 |
| 历史窗口重新分析 | `load_review_frames` / `fit_image`，同时覆盖存储帧和文件后备解码 | 569 x 480 |

示例的原始取右侧画面为 2880 x 2160。各模型仍按原有的尺寸上限先缩小，再裁去右侧窄条，不放大、不拉伸；模型自身后续标准缩放逻辑不变。

处理后的 PIL 副本会移除待执行的 `analysis_crop_right_fraction`，并保留 `analysis_applied_crop_right_fraction`。因此同一张历史图再交给 SurgR1，或多次经过 VLM 图片编码时，不会重复缩窄。原始共享图片上的配置元数据仍保留，让其他独立模型分支各自得到正确裁剪。

每个窗口的 `others.timing` 保存 `analysis_crop_right_fraction` 和 `expert_input_sizes`，可以核对实际生效比例，而不是只凭配置推断。

### 已发现但不能归为图标问题的残留

- SurgR1 在开头部分无器械画面仍输出抓钳候选。当前核验没有把这些写进前八个窗口的最终描述。不能仅凭图标被裁掉就认为 SurgR1 的幻觉已经消失。
- Triplet 的输出是候选排序，不是每个 top-1 都是阳性。开头抓钳牵拉胆囊三元组分数仅约0.001-0.002，不能忽略分数而直接当成已发生操作。
- 约1:55-2:05（界面窗口24、25）阶段显示胆囊分离，随后又回到准备。现有状态构建器会忽略缺少夹闭前序的胆囊分离记录，而显示阶段规则在这条前序上没有一致拦截，产生阶段状态不一致。本次裁剪没有修订整套阶段推进规则，也不能宣布全片阶段已准确。
- 实际术野中的具体组织、动作仍需独立核对，本报告是软件复测记录，不是临床确认报告。
