# Video Processor 技术概要

> 文档版本：2026-09-02
> 项目：Video Processor / Video Stream Analyzer
> 当前应用场景：腹腔镜胆囊切除术视频的本地实时分析、复盘与报告生成

## 1. 项目概述

Video Processor 是一套运行于 Ubuntu + Electron 的手术视频智能分析系统。系统接收真实采集卡、网络视频流或有限时长的本地视频，将连续视频切分为 5 秒窗口，通过多个轻量级手术专家模型和本地多模态大模型协同分析，实时输出手术阶段、器械、动作、目标组织、关键事件和安全相关提示，并支持窗口回看、事件导航、智能问答与临床总结报告。

当前部署以 3 张 RTX 4090 为主要算力环境。核心推理链路可以完全在本地完成，不需要将手术画面上传到外部云端。系统定位是手术视频的智能观察、结构化记录和复盘辅助工具，不替代术者判断，也不直接作出诊断或治疗决策。

## 2. 我们主要解决的问题

连续手术视频具有时长长、信息密度不均、事件持续时间短、视觉遮挡多和时序约束强等特点。只对单帧调用通用视觉模型容易产生以下问题：

- 忽略上下文，把短暂器械或高光误判为临床事件；
- 手术阶段在相邻窗口间来回跳变，出现不符合流程的阶段回退；
- 混淆外观相似的电凝钩、剪刀、施夹器、抓钳和已释放夹子；
- 将普通血染、红色创面或焦痂误报为活动性出血；
- 难以在实时速度、分析深度、GPU 资源和隐私保护之间取得平衡；
- 最终结果停留在逐帧文本，无法直接服务于回看、质控和报告生成。

本项目的主要工作，就是把模型识别、时序规则、实时系统工程、结果验证和 Electron 交互整合成一条可运行、可复查、可审计的端到端链路。

## 3. 当前技术架构

```text
采集卡 / HTTP、RTSP、WebRTC / 本地有限视频
                    |
                    v
        实时采帧与 5 秒窗口切分
          （1 秒采样 1 帧）
                    |
                    v
       多个专家模型并行生成证据
    +----------------+----------------+
    |                |                |
阶段专家         Triplet 专家      器械/夹子 YOLO
ResNet-18        LAM-Lite          检测与跨帧聚合
    +----------------+----------------+
                    |
                    v
       本地 Qwen3-VL-8B 结构化复核
  通用视觉判断 + 夹子/剪刀/视野专项复核
                    |
                    v
       证据门控、冲突裁决与时序状态机
                    |
                    v
  窗口摘要 / 关键事件 / CVS 状态 / 临床报告
                    |
                    v
       Electron 时间轴、一览、问答与回放
```

### 3.1 输入与窗口化

- 支持真实采集卡、HTTP/RTSP/WebRTC 视频流和本地视频。
- 本地视频可以通过 `filesim://` 按真实时间节奏模拟有限实时流，并正确处理 EOF。
- 默认窗口长度为 5 秒，每秒采样一帧；只有完整窗口才进入正式分析，避免同一窗口被半成品结果反复覆盖。
- 实时帧采用保留时长和定期裁剪策略，防止长时间运行持续占满磁盘。

### 3.2 多专家并行分析

| 专家 | 当前实现 | 主要输出 |
|---|---|---|
| Phase Expert | ResNet-18 | 胆囊切除术阶段及置信度 |
| Triplet Expert | LAM-Lite | 器械、动作、目标组织三元组 |
| Tool Expert | YOLO26s | 抓钳、电凝钩、剪刀、施夹器等器械证据 |
| Clip Expert | 标签修正后的 YOLO 检测器 | 已释放夹子候选及跨帧持续性 |
| 视觉线索 | OpenCV 规则 | 可见度、颜色和器械形态的辅助证据 |

专家模型负责快速、可解释的结构化判断。它们不是简单投票，而是把各自擅长的证据交给后续融合层处理。

### 3.3 本地多模态复核

系统通过 vLLM 部署 `Qwen3-VL-8B-Instruct`，对每个完整窗口的代表帧进行一次通用结构化分析，并在候选窗口追加专项复核：

- 夹子复核：区分已释放夹子、施夹器、剪刀、电凝钩和高光；
- 剪刀复核：确认是否存在双刃剪刀形态，降低电凝钩白色绝缘头造成的误报；
- 视野复核：区分腹腔内标本袋、镜头起雾、套管过渡和镜头移出体外；
- 综合判断：覆盖标本袋、纱布、活动性出血、CVS、器械和目标组织等字段。

当前线上链路关闭额外的异步 Stage 2 摘要覆盖，仅保留“专家即时结果 -> 同窗口结构化本地 VLM 复核”。这避免了晚到的第二次摘要破坏已经通过证据规则校验的结果。

### 3.4 时序一致性与证据门控

系统从历史窗口重建手术状态，并执行确定性约束：

- 手术进入夹闭切断、胆囊床分离、装袋或取出后，不允许无证据回退到早期阶段；
- CVS 未确认时出现剪刀，只生成“需核查”的风险节点，不虚构已经剪断；
- “剪断”需要 CVS、既往夹闭和当前剪刀证据共同支持；
- 检测到施夹器不等于已经释放夹子，夹子结论还需跨帧持续性或 VLM 确认；
- 普通血染、红色创面和电凝焦痂不等于活动性出血；
- 装袋后的短暂体外画面不直接等于标本已经取出；
- 专项复核对冲突结论具有最终否决权。

这些规则把“单帧看起来像”转化为“跨帧证据和手术流程共同支持”，是系统降低误报和阶段抖动的关键。

### 3.5 产品与结果层

- Electron + Vue 3 提供视频播放、实时摘要、窗口时间轴和窗口一览；
- 关键事件节点支持阶段、CVS、安全风险、夹闭、剪刀、装袋、取出、出血、起雾和体外场景导航；
- 每个视频可生成独立 Markdown 临床复盘报告；
- 智能问答基于当前会话和历史窗口回答问题；
- MySQL 保存会话、窗口分析和对话数据，`sessions/` 保存必要的帧证据；
- 离线工具可生成带摘要和事件字幕的复查 MP4、JSON、SRT、质量报告和汇总文档。

## 4. 核心 Contributions

### Contribution 1：隐私友好的本地端到端手术视频分析

项目将视频采集、专家模型、本地 VLM、数据库和 Electron 客户端部署在同一工作站，主分析链路不依赖外部 GPT/Gemini。相比只提供模型接口的原型，这是一套从输入到临床复盘输出的完整本地系统，更适合数据敏感的真实手术环境。

### Contribution 2：专家模型与通用 VLM 的分层协作

系统没有让一个大模型承担所有任务，而是让 Phase、Triplet、Tool 和 Clip 专家并行提供低延迟证据，再由本地 VLM处理视觉歧义。该设计兼顾专家模型的速度与专业先验，以及 VLM 的开放视觉理解能力。

### Contribution 3：面向手术场景的证据门控与冲突裁决

项目针对夹子、剪刀、CVS、出血、标本袋、起雾和体外场景建立了显式证据条件，并规定专家、通用 VLM 和专项复核发生矛盾时的处理顺序。输出不仅包含结论，还保留原始专家证据，便于回溯模型为何作出判断。

### Contribution 4：跨窗口手术状态机

项目把手术阶段的不可逆关系、先夹闭后剪断、装袋与取出顺序等知识编码为跨窗口状态。它处理的不只是同一帧内的冲突，还处理相邻窗口和长视频范围内的阶段矛盾，使摘要更接近连续手术过程，而不是互不关联的图片描述。

### Contribution 5：面向实时性的推理和 GPU 工程

系统使用 5 秒窗口、并行专家、vLLM 原生并发、双实例视觉负载均衡和长文本定向路由。主 VLM 使用 12K 上下文，辅助实例处理短图像请求；事件和报告等长文本固定送往主实例。该方案在三张 RTX 4090 上兼顾实时覆盖和长视频总结。

### Contribution 6：从识别结果到可用工作流

项目提供实时 Electron 界面、窗口一览、关键事件跳转、自然语言问答、医生复盘报告和带字幕复查视频。系统输出可以被检索、回放、审阅和导出，而不只是终端中的模型响应。

### Contribution 7：可复现的验证与数据质量治理

项目建立了并行批量分析、结果回填、视频重渲染和自动质量门禁工具，检查窗口连续性、VLM 收敛、事件重复、文本与结构化字段矛盾以及复查视频时长。训练侧还发现了自动标注中的系统性漏标和伪标签污染，并形成“VLM 预标注 -> 自动 QA -> 人工抽审 -> 训练 -> 预测图复查”的闭环。

## 6. 验证结果与已有证据

截至 2026-07-13 的本地验收记录包括：

- 三条完整 Cholec80 视频共覆盖 `1:52:59.12`，产生 1,357 个连续窗口；三条 `quality_report.json` 均为 `pass`，无 error/warning；
- 在这三条视频及其 Cholec80 阶段标注上，阶段有效准确率分别为 video01 `99.71%`、video05 `100%`、video09 `100%`，且没有缺失阶段；
- 100 秒 Electron 会话完整处理窗口 `0..19`，自然到达 EOF，视频在结束前未检测到超过 1 秒的新增冻结；
- 四个专项片段覆盖夹闭/分离、装袋/取出、体外和起雾恢复，自动质量报告全部通过；
- 复查 MP4 的分辨率、25 FPS、时长和总帧数与源视频一致，没有因字幕烧录导致丢帧或变速；
- 运行时泛化测试禁止根据视频名、session id、固定窗口号或固定时间戳硬编码分析结论。

这些结果证明了当前工程链路在既定 Cholec80 回归集上的连续性、时序一致性和可运行性，但不能等同于多中心临床有效性证明。

## 7. 对现实场景的意义

### 7.1 降低长视频复盘成本

系统把数十分钟到数小时的视频组织为可检索窗口和关键事件，医生、研究人员或质控人员可以直接跳到夹闭、剪刀、装袋、出血或视野异常等片段，而不必从头观看整段视频。

### 7.2 辅助手术安全复核

CVS 状态、夹闭与剪断顺序以及剪刀风险节点可以帮助术后回顾关键步骤是否具有足够视觉证据。系统采用保守措辞和证据门控，适合作为提醒与复核入口，而不是自动裁决工具。

### 7.3 支持教学与技能评估

阶段时间轴、器械动作三元组和事件片段可以帮助学员理解标准流程，也可为后续建立操作效率、流程偏差和技能评估指标提供结构化基础。

### 7.4 支持临床研究和数据治理

结构化窗口结果可以加速病例筛选、队列构建和标注复核。系统保留专家原始证据和质量报告，使研究者能够审计结果来源，而不是只得到不可解释的最终文本。

### 7.5 适合隐私敏感环境部署

本地推理减少了视频离院和第三方 API 依赖，适合医院内网、教学中心和手术机器人工作站。即使外网不可用，核心分析仍可运行。

### 7.6 为实时手术智能平台提供基础设施

统一的采集、窗口、模型融合、事件和报告接口可扩展到其他腹腔镜术式、机器人手术和内镜场景。项目的价值不仅在一个分类模型，也在于可复用的实时多模型协作框架。

## 8. 技术栈与部署形态

| 层级 | 主要技术 |
|---|---|
| 桌面客户端 | Electron、Vue 3、Vite |
| 后端 | FastAPI、异步任务、SSE/REST |

| 视频 | OpenCV、FFmpeg、WebRTC/HTTP/RTSP、采集卡输入 |

三卡 4090 的当前分工是：GPU0 运行 Phase/Triplet，GPU1 运行 Tool/Clip 并可承担辅助 VLM，GPU2 运行主 VLM。视觉请求可以通过负载均衡器在主/辅助实例间分配，长文本请求固定到长上下文主实例。

## 9. 当前边界与风险

- 当前重点验证对象是 Cholec80 和腹腔镜胆囊切除术，不能直接宣称对其他术式、医院或设备同样准确；
- Cholec80 缺少可信的逐帧 CVS 三要素金标，CVS 阳性识别仍需医生标注的独立数据集验收；
- 目标组织、活动性出血、纱布和小夹子仍是小目标、遮挡和域偏移敏感任务；
- 阶段准确率来自三条完整视频的内部回归，不代表全量 Cholec80 或外部数据集表现；
- 本地 VLM 和规则可能同时继承训练数据偏差，专项复核不能替代临床审核；
- 系统当前应定位为研究与辅助复盘软件，进入临床使用前还需要多中心前瞻性验证、风险管理、可用性测试和相应监管流程。

## 10. 后续工作建议

1. 建立医生标注的 CVS、活动性出血、纱布、夹子和剪刀阳性/阴性专项测试集。
2. 在未见视频、不同医院、不同采集卡、不同曝光和烟雾条件下分层评测召回率、误报率和延迟。
3. 将事件级指标与阶段级指标分开报告，补充置信区间和失败案例分析。
4. 继续扩充真实小目标标注，避免依赖纯自动伪标签和简单过采样。
5. 增加服务守护、磁盘配额、日志限速、GPU OOM 自动恢复和运行状态监控。
6. 在医生参与下评估报告可读性、回看效率和风险提醒的实际价值。
7. 将统一事件数据契约扩展到更多术式，验证多专家框架的可迁移性。

本项目的核心贡献，是把多专家模型、本地多模态模型、手术时序知识和实时桌面工作流组合成一套隐私友好、可解释、可复查的手术视频分析系统，并通过长视频回归和自动质量门禁验证其工程可用性，同时明确保留临床验证边界。
