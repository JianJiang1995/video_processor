# 软件界面录屏

## 使用

在 Electron 分析界面右上角点击“开始录屏”。按钮变红并显示录制时长；再次点击停止并保存。旁边的文件夹按钮打开保存位置。

录制的是整个软件窗口，包括视频、窗口分析、关键事件、智能问答和回看弹窗，不是只导出原视频。离线文件分析、模拟流和真实采集卡共用这一功能。纯浏览器打开页面时不显示按钮。

录屏不调用模型、不上传文件、不录麦克风、不录桌面其他应用。原始视频和分析数据仍按各自现有机制保存，录屏不能替代原始数据归档。

## 自动录制

右上角录屏设置图标中有“分析时自动录制（资源允许时）”复选框。初次默认关闭；开启后在本机记住设置，下次开始分析时自动录屏。导入已分析结果进行回放不会自动录制，可手动点击录屏。

本机已于 2026-09-23 完成 18 分钟原速分析与录屏联合验证，并开启此设置。新安装仍默认关闭，避免在未经测试的机器上自动增加负载。

自动开始前检查：

- 可用磁盘至少 2 GiB。
- 可用内存至少 2 GiB。
- 系统一分钟平均负载除以逻辑 CPU 数不大于 0.8。

负载判断只是保守准入检查，不代表 GPU 推理延迟一定满足要求。录制帧率默认 40fps，可在设置中选 1–60fps、画面最长不超过 1920×1080，并保留窗口比例；不更改采集分辨率、分析采样或源时间戳。自动录制与实际延迟还需要在目标设备上联合验证。

自动录制在分析退出后保留约 8 秒画面再收尾。手动开始的录制需要手动停止，也会在离开当前会话、关闭软件时收尾。暂停视频不会暂停录屏，因此能保留暂停和问答操作。

## 保存位置与格式

当前源码运行环境：

```text
/home/user/proj/video_processor/video_stream_app/recordings/ui/YYYY-MM-DD/
```

文件名包含 UTC 时间、会话 ID 和随机标识，不覆盖旧文件。每段录制有两个文件：

- `.mp4`：H.264 软件窗口录像，不含音频。
- `.mp4.json`：录制起止时间、会话 ID、停止原因、写入字节数等审计元数据。不是视频分析报告。

打包安装版保存到当前用户的系统“视频”目录下 `SurgR1/recordings/`。

录制时直接编码为 H.264 MP4，并逐秒写盘，不需要手动转格式。停止后利用本机 FFmpeg 做流复制，整理时长、索引及 faststart，不重新编码。若该步骤失败，会保留已写入的原始分片 MP4，并显示索引警告。当前 Electron 已实测支持；若其他桌面运行环境不支持 H.264 MP4，会在开始前明确报错。旧 WebM 录像保持原样。

## 清晰度与原始输入的区别

默认录屏参数为最高 1920×1080、40fps、目标视频码率 4.5Mbps，H.264 有损编码。它不是原始术野的无损副本：例如 4K/50fps 输入展示在窗口中的视频区域后，再和分析文字一起录入成片。窗口超过 1080p 时会缩小，窗口比例不同则实际高度也不同，窗口内的视频区域只占成片的一部分。录屏设置不会改变采集卡输入或模型采样。

保存时通过本机 `ffprobe` 读取成片参数。同名 `.mp4.json` 的 `requestedEncoding` 是设定参数，`media` 是实测分辨率、平均帧率、视频码率及总时长；`media` 为 `null` 时表示未能验证，不能用设定值代替。界面也会提示索引或格式验证失败。实际帧率不保证达到设定帧率，静止窗口及系统负载都可能降低成片平均帧率。

## 异常与限制

- 每秒将编码块顺序写盘，不把整场录像积存在内存。积压超过 32 MiB 时停止录制。
- 每 10 秒检查磁盘，可用空间低于 512 MiB 时停止录制并保留已写入内容。
- 录屏失败不取消视频分析，也不改变播放时间轴。
- 缩放窗口不使用旧版固定尺寸的 `x11grab -window_id` 管线；捕获目标仍是本软件窗口。
- 最小化窗口会停止录屏，避免得到无法确认内容的最小化画面。需要长录时保持窗口打开。
- 正常关窗会等待录制收尾。强制杀进程、系统断电或磁盘损坏时，不能保证最后一块数据和索引完整。
- 页面异常退出时主进程会尝试恢复已写入的块；这不等于能找回尚未写入的最后一秒。退出原因保存在同名审计文件中。
- 录屏帧率可选 1–60fps（默认 40fps）；实际帧率受窗口更新及整机负载影响，不应拿它测量原始视频的逐帧流畅度，也不是无损原始术野归档。

## 实现与测试

- `frontend/src/components/ScreenRecordingControl.vue`：按钮、时长、设置、自动开始及停止。
- `frontend/src/utils/screenRecorder.js`：窗口媒体流、MediaRecorder、写入背压和错误收尾。
- `frontend/electron/preload.cjs` / `main.cjs`：限定本窗口的 IPC，资源检查和关闭保护。
- `frontend/electron/screenRecording.cjs`：本地文件、顺序追加、索引与审计记录。
- `scripts/verify_surgr1_updates.py --app-recording`：实际 Electron 自动录制和真实推理检查，不是离线结果回放伪装成实时分析。
- `scripts/verify_screen_recording.py`：连接专用测试 Electron，验证语言切换、缩放和窗口管理器关闭消息。该脚本会关闭测试窗口，不应指向正在分析的生产窗口。

```bash
cd /home/user/proj/video_processor/video_stream_app
node --test frontend/tests/*.test.js
```

录屏采集使用当前 Electron 窗口的 `getMediaSourceId()`，接口定义见 [Electron BrowserWindow 文档](https://www.electronjs.org/docs/latest/api/browser-window#wingetmediasourceid)。

### MP4 与真实推理联合验证（2026-10-14）

实际启动本机 Electron、Qwen3-VL、SurgR1、YOLO 和 Triplet 等服务，使用 `09-40-30.mp4` 的前 60 秒做原速模拟输入，进行多轮对照和操作验证。不是导入已有分析结果。源为 4K/50fps 四分图，沿用已有 1920×1080 / 25fps 文件预览代理及右侧视图裁剪；分析仍读取原始源并低帧率采样。不能把这些预览指标当作 SDI 原生预览指标。
