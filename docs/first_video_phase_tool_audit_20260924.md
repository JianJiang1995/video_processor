### 3.3 跟踪器持久化错误

`backend/services/yolo_service.py:65` 预热调用 `track(..., persist=False)`。本机 Ultralytics 8.4.60 在第一次调用时把 `persist=False` 绑定到跟踪回调；后续 `detect()` 虽然传入 `persist=True`，却不会重新绑定回调。

独立复测确认：连续调用后，内部跟踪器 `frame_id` 始终为 1，跟踪 ID 重置复用；而本服务 `_class_votes` 按同一个 ID 保留旧类别投票。因此右下角的抓钳误检与右上角的双极误检会共享 ID 1，后者被旧投票改成抓钳。证据：`tracker_callback_reproduction.json`。

这说明存在三个层次的问题：模型把设备图标误检为器械；跟踪平滑把不同对象的类别混在一起；摘要把弱检测直接发布。只改 Prompt 或单纯提高阈值不能完整解决。

### 3.4 SurgR1 也不能当作无条件确认

原记录中，SurgR1 对 5.0404 秒给出 `grasper null_verb null_target`，对 9.8410 秒、15.0414 秒、19.8618 秒给出 `grasper retract liver`。对应保存图中未看到可确认的抓钳，这些输出不能作为抓钳存在的独立可靠证据。

当前问题提示词要求描述完整器械-动作-组织，见 `backend/services/surgr1_window_review.py:11`，没有明确列出无器械/无法判断的输出要求。这是需要验证的提示词风险，不足以证明 Prompt 是唯一根因。最终本地 Qwen3-VL-8B-Instruct 复核后，两处抓钳已被删除，但实时初稿先向用户显示了错误。

3. 所有器械采用一致的证据门槛，并校验位置、连续性与原始类别。不能仅增加多帧门槛：固定设备图标也会连续多帧误检。
4. 处理设备叠加图标时使用可配置输入源有效区或通用叠加层识别，不能硬编码这个视频的时间、右上角坐标或窗口号，也不能盲目删除所有边缘区域而漏掉真实入镜器械。
5. 保持快初稿与异步 SurgR1/VLM 更新分离；允许明确输出“无可确认器械/动作”。SurgR1 输出必须接受图像与检测证据核对，不能因为它是专家就直接采信。
6. 保存样本时间、原始框、原始类别、平滑类别、分数、采纳/拒绝原因和阶段纠正轨迹，便于准确追责。
7. 先用本次负样本和其他视频真实器械入镜片段做回归，再重跑完整视频验证阶段、事件、报告。规则不应为满足预期流程而抹去真实观察到的异常动作。

验收不只是“后续把错误删掉”，还包括：无器械画面初稿不发布假器械；真实器械短暂入镜不过度漏检；阶段可纠错但不频繁跳变；总结不继承错误锁死阶段；不增加初稿等待 SurgR1 的延迟。
