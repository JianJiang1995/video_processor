## 本次显示约定

1. 阶段单独显示为小标签，来自保存的阶段字段；兼容 snake_case/canonical 命名，未知阶段显示“阶段待确认”。不根据文案猜阶段。
2. 正文优先说明实际器械、动作、可辨认对象及进展。有动作时不能只剩组织颜色或表面纹理；无可辨认动作时允许只描述术野。
3. 不为了主谓宾完整而把未知器械、管状结构或普通血管改成具体器械、胆囊管、胆囊动脉。
4. CVS 纯状态放在独立关键节点，普通窗口不反复显示；涉及剪刀、夹闭、出血或风险的 CVS 句子保留。
5. 网格卡片、回放弹窗、右侧分析使用同一个显示整理函数。网格只是预览截短，悬停可看完整文字，回放里保留全文。

## 根因与修复

### 展示端错误精简

原 `RightPanel.vue`、`WindowOverview.vue` 有大量正则：删掉“抓钳”等动作主体，甚至将管状结构残端直接改为胆囊管残端。
历史合并还会因前 8/12 个字相同而去掉后半句不同的动作对象。

现统一在 `frontend/src/utils/windowNarrative.js` 中处理，仅去阶段标题、独立 CVS 状态、完整重复句，不再做临床事实改写。
历史分组合并要求：相邻、同阶段、已视觉复核、文本相似度达到 0.65；最多 6 窗口，每段最多 320 字。
不同的新句保留；超过上限时新开一组，不静默丢掉后来的剪断或出血信息。
原始窗口记录保持独立存储。

### 本地复核上下文丢失

实时路径原来把丰富提示直接替换为 `LOCAL_VISUAL_PROMPT`，没有传入专家候选；手动重新分析也没有使用保存的专家结果。

现在实时/手动路径共同调用 `build_local_visual_prompt`：

- 同窗口的阶段、YOLO 器械及支持帧数，最多 8 种器械。
- 最多 4 条原始动作三元组候选及置信度，不复制旧摘要、形态学规则文案或旧 VLM 判断。
- 排除零/极低分、空动作/空目标；YOLO 已返回清单时，不发送与清单器械冲突的动作候选。
- 候选只是提示，必须重新核实图像；没有候选不等于没有器械。置信度不等于真实准确率。
- 模型先输出可定位的观察，再输出摘要；所有患者图像仍只发到本机模型。

当前服务是本地 `Qwen3-VL-8B-Instruct`，手动复核最多 4 张、最长边 640；实时图像数量仍由配置控制（当前 3 张）。
没有新增一次摘要 API 调用。已有夹子、剪刀、视野二次核实路径没有被移除。
外部 GPT 分支的提示词未修改。

### 完整性与耗时

新增观察字段后，把本地视觉输出预算从原来的 512 提高到至少 1400 token，手动复核同为 1400。
本地结果缺少非空 summary/visual 时，不作为成功结果覆盖窗口。没有增加视频采样帧率或改变播放方式。

这不是“5 秒内得到最终判断”的保证：本轮离线抽样复核约 8.2–9.1 秒一次，实时仍先展示专家结果，再异步更新。
提高 token 上限只是允许完整输出，实际延迟还取决于生成长度和并发。不能把即时专家结果与最终复核延迟混为一谈。
检查旧会话 `61501999` 时，129 条有 raw 的结果都能解析为 JSON，因此没有把截断说成该会话已经证实的故障原因。
